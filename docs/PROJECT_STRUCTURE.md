# Project structure

This file is now a pointer. The structure is described in **[`REPOSITORY_MAP.md`](../REPOSITORY_MAP.md)**
at the repository root, which is generated from the tree itself and therefore cannot go out of date
the way this document did.

Two machine-readable indexes sit beside it:

| File | Contents |
|---|---|
| `REPOSITORY_INVENTORY.csv` | every live file, with its category, size and whether it is committed |
| `SCRIPT_INDEX.csv` | every script in the order the pipeline runs it, with its purpose and outputs |
| `ARCHIVE_MANIFEST.csv` | every file moved to the archive, with its checksum and the reason |

## Why this file was replaced

It described a repository that no longer exists. It documented "two code lineages currently
coexist", naming `BS_predictive_model.py`, `app_v6_final.py`, `ml_v5_engine.py` and their siblings as
the working pipeline. That migration finished: those scripts were rewritten as modules under
`src/brainsafe/` and retired, and none of the named files is in the tree. It also pointed to
`BrainSafe_AI_Publication/` and `archive/legacy/`, both of which have since been consolidated into
the dated archive folder recorded in `ARCHIVE_MANIFEST.csv`.

A hand-maintained structure document drifts silently, and a drifted one is worse than none, because
it is read as current. The replacement is generated by
`src/brainsafe/analysis/reorganise_repository.py`, so refreshing it is a command rather than an act
of memory.
